# t6 – בנק המבוכים (שלושה גדלים) – הסבר פשוט

קבצים: `lidar_sim/maze_bank.py` (הספרייה), `lidar_sim/build_maze_bank.py` (בונה את הבנק), `lidar_sim/test_maze_bank.py` (בדיקות), `lidar_sim/mazes/` (הבנק עצמו + `index.yaml`).

## 1. למה צריך את זה?

הרובוט שלנו "נחטף": הוא מתחיל בתא לא ידוע ורק החיישנים יכולים לומר לו איפה הוא. אם שני תאים נראים **בדיוק אותו דבר** לחיישנים, מבט אחד לא מספיק להבדיל ביניהם, והרובוט חייב לזוז ולאסוף עוד מידע. לכן מה שקובע כמה מבוך "קשה" ללוקליזציה הוא לא רק הגודל שלו, אלא כמה תאים בו **דו-משמעיים** (ambiguous). כדי להשוות מדיניות (ה-heuristic של פרויקט A מול ה-POMDP) בצורה הוגנת, צריך סט קבוע של מבוכים בשלושה גדלים (5×5, 10×10, 16×16), שבכל גודל יש מבוך קל, בינוני וקשה, וכל אחד עם ציון דו-משמעות שחושב מראש. זה הבנק.

## 2. איך מבוך מיוצג: `wall_map`

מערך numpy בצורה `(rows, cols, 4)` מסוג `uint8`. לכל תא `(r, c)` יש 4 ערכים, אחד לכל צד:

| ערוץ | קבוע | משמעות |
|---|---|---|
| 0 | `WALL_UP` | הצד הצפוני (שורה 0 היא העליונה) |
| 1 | `WALL_DOWN` | הצד הדרומי |
| 2 | `WALL_LEFT` | הצד המערבי |
| 3 | `WALL_RIGHT` | הצד המזרחי |

**`0` = קיר, `1` = פתוח** (שימו לב: הפוך מהאינטואיציה "1 = יש קיר"). כל קיר פנימי נשמר פעמיים, פעם מכל צד, ושני הצדדים חייבים להסכים.

דוגמה אמיתית, `mazes/small/m5_c.txt` (מבוך 5×5, `G` = תא המטרה):

```
     c=0 c=1 c=2 c=3 c=4
    +---+---+---+---+---+
r=0 |   |               |
    +   +---+---+   +   +
r=1 |       |       |   |
    +---+   +   +---+---+
r=2 |       | G         |
    +   +---+---+---+   +
r=3 |   |       |       |
    +   +   +   +   +   +
r=4 |       |       |   |
    +---+---+---+---+---+
```

תא המטרה `(2, 2)`: מעליו אין `---` (פתוח), מתחתיו יש `---` (קיר), משמאלו `|` (קיר), מימינו רווח (פתוח). ולכן:

```python
spec.wall_map[2, 2]   # -> [1 0 0 1]   (UP=1 פתוח, DOWN=0 קיר, LEFT=0 קיר, RIGHT=1 פתוח)
```

`validate_wall_map` בודק שמבוך תקין: הגבול החיצוני סגור, שני הצדדים של כל קיר מסכימים, וכל התאים נגישים מ-`(0, 0)`. עובד לכל גודל (בניגוד לגרסה של פרויקט A שקשורה ל-15×20).

## 3. מדד הדו-משמעות (ambiguity)

### האינטואיציה
הרובוט עומד בתא ו"מסתכל" ב-4 כיוונים קבועים (צפון/דרום/מערב/מזרח של המפה, לא יחסית לכיוון הרובוט). מכל כיוון הוא מקבל מספר. רביעיית המספרים היא ה**חתימה** (signature) של התא. שני תאים עם אותה חתימה הם תאים שהרובוט לא יכול להבדיל ביניהם במבט אחד.

### בדיוק
- **`d`** (בפונקציה `ray_distances`): לכל תא וכיוון, כמה תאים פתוחים הקרן עוברת עד הקיר הראשון. במילים אחרות, כמה צעדים אפשר ללכת בכיוון הזה. `d = 0` אומר שיש קיר על הצלע של התא עצמו.
  בדוגמה: התא `(2, 2)` מקבל `d = [1, 0, 0, 2]` (למעלה תא אחד, למטה ושמאלה קיר צמוד, ימינה שני תאים).
- **טווח `R`** (בפונקציה `sensor_signature(wall_map, R)`): החיישן המתוכנן רואה רק עד `R`. הקריאה היא `d` אם `d <= R`, אחרת **`NONE`** (שערכו `-1`), כלומר "לא ראיתי קיר בטווח". עם `R=1` התא `(2, 2)` קורא `[1, 0, 0, NONE]`. עם `R=None` מקבלים את `d` בלי הגבלה.
- **קבוצות**: `signature_groups` מקבצת את כל התאים לפי החתימה. מכל חלוקה כזו `group_stats` מחשבת (N = מספר התאים):

| שדה | מה זה | |
|---|---|---|
| `n_shared` | כמה תאים חולקים חתימה עם לפחות תא אחד נוסף | המספר הראשי. זה בדיוק `ambiguity_score` של פרויקט A |
| `n_distinct` | כמה חתימות שונות יש | |
| `amb` | `1 - n_distinct / N` | 0 = כל תא ייחודי |
| `largest_group` | גודל הקבוצה הגדולה ביותר של תאים זהים | המקרה הגרוע |
| `H1` | `sum_g (|g|/N) * ln|g|` (ב-nats) | ראו למטה |

**`H1` במילים:** מתחילים מאמונה אחידה (הרובוט יכול להיות בכל תא). הוא מסתכל פעם אחת, בלי רעש. אם הוא נמצא בקבוצה בגודל `|g|`, נשארים לו `|g|` מועמדים שווי-סיכוי, כלומר אנטרופיה `ln|g|`. ההסתברות ליפול בקבוצה הזו היא `|g|/N`. `H1` הוא הממוצע. הדרך הנוחה לקרוא אותו: **`e^H1` הוא "כמה תאים, בערך, הרובוט עדיין לא מצליח להבדיל ביניהם אחרי מבט אחד"**. `H1 = 0` (`e^H1 = 1`): מבט אחד מספיק. `H1 = ln N`: המבט לא נתן כלום.

### דוגמה ביד: מסדרון 1×7

```
+---+---+---+---+---+---+---+
| 0   1   2   3   4   5   6 |
+---+---+---+---+---+---+---+
```

למעלה ולמטה תמיד קיר (`d = 0`), אז רק שמאל/ימין מעניינים. לתא `c`: שמאל = `c`, ימין = `6 - c`.

| תא `c` | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| ללא הגבלה (שמאל, ימין) | 0,6 | 1,5 | 2,4 | 3,3 | 4,2 | 5,1 | 6,0 |
| `R=2` | 0,N | 1,N | 2,N | N,N | N,2 | N,1 | N,0 |
| `R=1` | 0,N | 1,N | **N,N** | **N,N** | **N,N** | N,1 | N,0 |

(N = `NONE`). ללא הגבלה ועם `R=2` כל 7 התאים ייחודיים: `n_shared = 0`, `H1 = 0`. עם `R=1` שלושת התאים האמצעיים לא רואים אף קיר ונראים זהים: `n_shared = 3`, `n_distinct = 5`, `amb = 1 - 5/7 = 0.286`, `largest_group = 3`, `H1 = (3/7)·ln 3 = 0.471`, `e^H1 ≈ 1.6`. (זה בדיוק `test_ambiguity_1xN_corridor`.)

### ללא הגבלה (פרויקט A) מול מוגבל-R
- **`unbounded`**: החתימה של `score_map` בפרויקט A, שבה כל קרן מודדת מרחק עד הקיר בלי הגבלת טווח. נשמר לצורך המשכיות עם פרויקט A (יש בדיקה שמוודאת ש-`n_shared` שלנו שווה ל-`ambiguity_score` שלהם על 10 המפות שלהם).
- **`limited`** (`R1`, `R2`, `R3` באינדקס): מה שהחיישן המתוכנן באמת רואה (קרניים בטווח `R`, בלי רעש). `ambiguity(wall_map, R)` מחזירה את שתי הגרסאות: `{"R": R, "unbounded": ..., "limited": ...}`.
- **למה `R=1` קשה יותר מ-`R=2`:** כל מרחק גדול מ-`R` מתמזג לאותו `NONE`. עם `R=1` יש לכל קרן רק 3 קריאות אפשריות (`0`, `1`, `NONE`), ועם `R=2` יש 4. הגדלת `R` רק **מפצלת** קבוצות (תאים עם `d = R+1` נפרדים מתאים עם `d` גדול יותר), ואף פעם לא מאחדת. לכן הדו-משמעות יורדת (או נשארת) ככל ש-`R` גדל, ו-`unbounded` הוא הגבול התחתון. בטבלה בסעיף 5 רואים את זה: ה-`n_shared` של `R1` תמיד הכי גבוה (או שווה), וזה של `unbounded` הכי נמוך.

## 4. איך המבוכים נוצרים

### הגנרטור: `generate_maze(rows, cols, seed, loop_fraction)`
1. **DFS (recursive backtracker)**: מתחילים ממבוך סגור לגמרי ומתא `(0, 0)`. בכל צעד בוחרים באקראי שכן שעדיין לא ביקרנו בו, פותחים את הקיר אליו ונכנסים. אם אין שכן כזה, חוזרים אחורה. התוצאה היא **מבוך מושלם** (perfect maze, עץ פורש): בדיוק מסלול אחד בין כל שני תאים. זה העתק של `map_generator._dense_photo_maze` מפרויקט A, עם `rows, cols` כפרמטרים (עם אותו seed על 15×20 יוצא אותו מבוך, ויש לזה בדיקה).
2. **הזרקת לולאות**: מכל הקירות הפנימיים שנשארו סגורים אחרי ה-DFS, פותחים באקראי `round(loop_fraction * n)`. `loop_fraction = 0` = מבוך מושלם, `1` = קופסה ריקה. זה מחליף את `loop_edges` שנבחרו ידנית בפרויקט A.

הכול נקבע מה-`seed` (`np.random.default_rng(seed)`), כך שאותו seed נותן תמיד אותו מבוך.

**למה לולאות מורידות דו-משמעות?** במבוך מושלם יש הרבה מבויים סתומים ומסדרונות קצרים, והם נראים אותו דבר: "קיר משלושה צדדים, פתוח למעלה" חוזר שוב ושוב. פתיחת קירות נוספים מאריכה קרניים ויוצרת צירופים מגוונים יותר, וכך יותר תאים מקבלים חתימה ייחודית. לכן **המבוכים המושלמים הם הקשים ביותר**. שימו לב: ב-roadmap (t6) כתוב "Loops create ambiguity", אבל המדידות מראות את ההפך: **לולאות מורידות את הדו-משמעות**. ה-sweep מאשר את זה: חציון `H1` (R=2) על 100 seeds הוא 0.055 / 0.166 / 0.222 ב-5×5 עבור `loop_fraction` = 0.35 / 0.1 / 0.0, ו-0.765 / 1.199 / 1.531 ב-16×16.

### איך נבחרו a / b / c בכל גודל (`build_maze_bank.py`)
לכל "מתכון" `(name, loop_fraction, quantile)` מייצרים 100 מבוכים עם seeds קבועים (5000..5099 ל-small, 10000..10099 ל-medium, 16000..16099 ל-large), ממיינים לפי `H1` של `R=2` (שוויון נשבר לפי seed), ולוקחים את המבוך באחוזון המבוקש (אינדקס `round(q * 99)`):

| | `loop_fraction` | אחוזון | כוונה |
|---|---|---|---|
| `a` | 0.35 | 0.10 | קל: הרבה לולאות, וגם מהקלים שבהם |
| `b` | 0.10 | 0.50 | בינוני: מעט לולאות, החציון |
| `c` | 0.00 | 0.95 | קשה: מבוך מושלם, מהקשים שבהם |

### מבוכי הצוות הקודם
ארבעה מבוכים הועתקו מ-`micromouse-py-sim` של Roy Abudi & Huly, תחת **רישיון MIT** (הקובץ `mazes/predecessor/LICENSE` נשמר לידם, וזה מה שהרישיון דורש): `simple` ו-`longer` (5×5), `japan_2017` ו-`semifinal_2009` (16×16, מבוכי תחרות אמיתיים). קבצי ה-`.maze` המקוריים נמצאים ב-`mazes/predecessor/` והומרו עם `maze_to_wall_map` (פורט של הפרסר שלהם). המטרה שלהם הוחלפה במטרה המרכזית של הבנק, כדי שלכל מבוכי אותו גודל תהיה אותה מוסכמה. ההתחלה והמטרה המקוריות נשמרות ב-`meta["source"]` (`original_start`, `original_goals`).

**המטרה (`center_goal`)**: בגודל אי-זוגי התא המרכזי (`(2, 2)` ב-5×5), בגודל זוגי בלוק 2×2 במרכז (`(4,4),(4,5),(5,4),(5,5)` ב-10×10, `(7,7)..(8,8)` ב-16×16).

### תווית הקושי (`difficulty`)
התווית **יחסית לגודל**. בתוך כל גודל לוקחים את **כל** המבוכים (כולל של הצוות הקודם) ומדרגים אותם לפי `H1` של `R=2`, מעוגל ל-6 ספרות:
1. לכל מבוך מחשבים **דירוג אמצעי** (mid-rank, מ-0): כמה מבוכים קטנים ממנו, ועוד חצי ממספר המבוכים האחרים ששווים לו. כך למבוכים עם אותו `H1` יש אותו דירוג.
2. מיקום = `mid_rank / (n - 1)`, כש-`n` הוא מספר המבוכים בגודל.
3. מתחת ל-1/3 זה `easy`, מתחת ל-2/3 זה `medium`, ואחרת `hard`.

דוגמה מ-small (5 מבוכים): `m5_a` (H1=0) מקבל מיקום 0, כלומר `easy`. ל-`longer` ול-`simple` יש אותו H1 (0.131833), ולכן דירוג אמצעי 1.5 ומיקום 0.375, כלומר שניהם `medium`. `m5_b` מקבל מיקום 0.75 ו-`m5_c` מיקום 1, ושניהם `hard`.

**האותיות a/b/c הן רק סדר המתכונים** (הכוונה הייתה מקל לקשה), והן לא התווית. למשל `small/m5_b` מסומן `hard` ו-`large/m16_b` מסומן `easy`, כי מבוכי הצוות הקודם נכנסו ביניהם בדירוג.

### איך זה נשמר
לכל מבוך: `mazes/<size>/<name>.npz` (שדות `wall_map`, `goal_cells`, `meta_json`) וגם ציור `.txt` לבני אדם, שנקרא בחזרה לאותו `wall_map` בדיוק (יש לזה בדיקה). `mazes/index.yaml` מכיל לכל מבוך את הגודל, המטרה, המקור והציונים. **הקובץ נוצר אוטומטית, לא לערוך ביד.** `load_maze` ממזג את ה-`meta` מה-`.npz` עם הרשומה מ-`index.yaml`.

**שמות:** שם מבוך הוא בדיוק `<size>/<name>`: רמה אחת בלי תיקיות נוספות, וכל חלק מכיל רק אותיות, ספרות, `_` או `-`. `load_maze` עובר דרך `resolve_name`, שמשווה את השם **בדיוק, כולל אותיות גדולות/קטנות**, לרשימה של `list_mazes()`. לכן `"MEDIUM/m10_a"` נכשל גם ב-Windows, למרות שמערכת הקבצים הייתה פותחת את הקובץ. שם קצר (`"m10_a"`) מתקבל רק אם הוא קיים בגודל אחד בלבד. יש שתי שגיאות `KeyError` שונות: "not found" לשם שלא קיים, ו-"ambiguous" לשם קצר שקיים ביותר מגודל אחד.

**`save_maze`** תמיד מסרב (`ValueError`) כשהשם לא בצורה `<size>/<name>`, כשה-`wall_map` לא בצורה `(rows, cols, 4)`, כשהגודל לא מתאים למחלקה (small=5×5, medium=10×10, large=16×16; שמות גודל אחרים כמו `custom/...` פטורים מהבדיקה הזו), או כש-`goal_cells` ריק או מחוץ למפה. עם `check=True` (ברירת המחדל) הוא גם מריץ את `validate_wall_map`.

## 7. מילון קצר

- **`wall_map`**: מערך `(rows, cols, 4)`, ערוצים UP/DOWN/LEFT/RIGHT, ‏`0` = קיר, `1` = פתוח.
- **קרן / `d`**: מספר התאים הפתוחים בכיוון קבוע עד הקיר הראשון (`ray_distances`).
- **`R`**: טווח החיישן בתאים. מעבר לו הקריאה היא `NONE` (`-1`).
- **חתימה (signature)**: רביעיית הקריאות של תא (`sensor_signature`).
- **`n_shared`**: מספר התאים שיש להם "תאום" עם אותה חתימה. המספר הראשי, זהה ל-`ambiguity_score` של פרויקט A ב-unbounded.
- **`amb`**: `1 - n_distinct / N`.
- **`largest_group`**: הקבוצה הגדולה ביותר של תאים זהים.
- **`H1`**: האנטרופיה הצפויה אחרי מבט אחד בלי רעש. ‏`e^H1` ≈ כמה תאים נשארים לא מובחנים.
- **מבוך מושלם (perfect maze)**: מסלול יחיד בין כל שני תאים, בלי לולאות. ‏`loop_fraction = 0`.
- **`loop_fraction`**: איזה חלק מהקירות הפנימיים שנשארו סגורים אחרי ה-DFS נפתח באקראי.
- **sweep / אחוזון**: 100 seeds קבועים לכל מתכון, ממוינים לפי `H1`. בוחרים את המבוך באחוזון שהוגדר.
- **`MazeSpec`**: מבוך שמור: `name, wall_map, goal_cells, rows, cols, meta`.
- **predecessor**: מבוכי הצוות הקודם (`micromouse-py-sim`, רישיון MIT).
